# 《Synapse》完整工程架构与开发设计文档（v3.1）

* **项目代号**：**Synapse**（突触）
* **系统定位**：极低功耗、极高隐蔽性的 Android 系统级微内核调度底座 + 端侧 Root AI 自主诊断智能体
* **适配范围**：**Android 11 – Android 17（API 30 – 37）**，原生支持 16KB 内存页与现代 `libxposed` API 101/102（LSPosed v2.0+ / Vector）
* **ROM 专项**：针对 **ColorOS（Hans / OFreezer / Athena）、HyperOS、OriginOS** 等重度定制系统提供非破坏性纯内存接管与 OTA 安全熔断

---

## 第 1 章：核心设计哲学与五大架构铁律

针对传统玩机/保活工具“耗电、易被风控、破坏系统设置且卸载无法恢复”三大痛点，本项目确立以下不可妥协的五大铁律：

1. **零破坏与 100% 可逆恢复（Non-Destructive Guarantee）**
   * **默认核心路径严格零落盘**：**绝不**修改 `/system`、`/vendor` 分区或挂载 `system.prop` / `resetprop` 全局系统属性；**绝不**篡改 `Settings.Global/Secure`、`device_config` 全局开关（如全局禁用冻结器）或 `/data/system/deviceidle.xml`；**绝不**执行 `pm disable` 禁用系统组件（如 `com.oplus.athena`）或第三方 App 组件（避免在 `/data/system/users/0/package-restrictions.xml` 留下永久残废状态）。
   * **可选高级调优强制走事务账本**：若用户在极少数场景下**显式授权**执行外部系统调优（如 OEM 关联启动放行或临时调试命令），强制经由 `MutationLedger` 记录基线并支持一键倒序回滚。
   * **结果**：在默认模式下，只要在框架管理器取消勾选 `Synapse`（或卸载 APK）并重启，系统与所有应用 **100% 无痕回归原厂状态**；即便使用过可选高级调优，执行“卸载前一键还原”后同样 100% 复原。
2. **双态彻底分离（Agent vs Micro-Kernel）**
   * AI 推理与 Root 探针**仅在用户主动打开管理端诊断时按需运行**，调优完毕立即退出；日常后台运行期间，`system_server` 内核只执行 $O(1)$ 哈希查找，0 轮询、0 AI 算力消耗。
3. **微内核热路径无锁化与内存克制**
   * `OomAdjuster`、`CachedAppOptimizer`、`NetworkPolicyManagerService`、`OplusHansManager`、`ActivityStarter` 等高频回调严禁使用 `synchronized` 锁或动态反射，全部使用 `@Volatile` 不可变配置快照与启动期缓存句柄。
   * 严控 `system_server` 内常驻内存占用与对象分配（零泄漏设计），避免触发 Android 17 **PMGD（Process Memory Guardian Daemon）** 对 `system_server` 的内存看门狗告警或重启。
4. **单点寄生，零进程注入**
   * 作用域通过 `META-INF/xposed/scope.list` 与 `staticScope=true` **硬锁死仅系统框架 (`android`)**，不向任何第三方 App 注入代码，天然免疫应用侧 `/proc/self/maps`、ART Hook 与调用栈检测。
5. **异常隔离与 OTA 熔断底线**
   * 所有内核 Hook 由安全隔离舱兜底，并内置系统指纹（`Build.FINGERPRINT`）校验：ROM OTA 升级后若检测到私有 OEM 钩子签名变更，自动旁路降级并向 UI 报警，绝不引发卡开机（Bootloop）。

### 2.3 Xposed 框架适配（双构建变体）与隐身构建策略

> **架构修正说明**：Legacy Xposed（API 82 / LSPosed v1.9.x）强制要求在 `AndroidManifest.xml` 中声明 `<meta-data android:name="xposedmodule" android:value="true"/>` 与 `assets/xposed_init`；若在**同一个 APK** 中混装 Modern 与 Legacy 入口，将直接破坏现代 `libxposed` “零 Manifest Xposed 特征”的隐身优势。因此采用 **Gradle `productFlavors` 分离打包**。

1. **主推 `modern` 变体（纯 `libxposed` API 101/102，适用于 LSPosed v2.0+ / Vector）**：
   * **准确依赖坐标**：
     * `kernel-engine`：`compileOnly("io.github.libxposed:api:102.0.0")`（最低兼容 `minApiVersion=101`，并按需声明 `targetApiVersion=102`）
     * `app`：`implementation("io.github.libxposed:service:102.0.1")`（用于 UI 侧绑定框架服务、读写 `RemotePreferences`）
   * **标准元数据布局**（位于 `src/modern/resources/META-INF/xposed/`，**`AndroidManifest.xml` 中零 Xposed meta-data**）：
     * `module.prop`：`minApiVersion=101`、`targetApiVersion=102`、`staticScope=true`（不建议对 `system_server` 开启 `autoHotReload`，避免内核态热重载导致状态撕裂）
     * `java_init.list`：仅包含继承 `io.github.libxposed.api.XposedModule` 的入口类全限定名
     * `scope.list`：硬锁定仅写入 **`system`**（现代 `libxposed` API 101/102 规范中 `system_server` 的作用域标识符为 `system`，区别于 Legacy API 82 的 `android`）
   * **API 101/102 入口契约**：入口类**必须提供公开无参构造函数 `public <init>()`**（不再接收 `XposedInterface` 构造参数），所有系统级 Hook 统一在 **`onSystemServerStarting(param: SystemServerStartingParam)`** 生命周期内执行。
   * **R8 必配规则**：
     ```proguard
     -dontwarn io.github.libxposed.annotation.**
     -adaptresourcefilecontents META-INF/xposed/java_init.list
     -keep,allowoptimization,allowobfuscation public class * extends io.github.libxposed.api.XposedModule {
         public <init>();
     }
     ```
2. **兼容 `legacy` 变体（API 82，仅用于旧版 LSPosed v1.9.x）**：
   * 仅在 `src/legacy/` 下保留 `AndroidManifest.xml` 中的 `xposedmodule` / `xposedscope` 与 `assets/xposed_init`，共享同一套 `kernel-engine` 内核核心逻辑，由适配层桥接 Hook 原语。
3. **构建期随机伪装**：
   * `app/build.gradle.kts` 首次构建时在 `local.properties` 持久化生成随机无特征包名（`com.local.utility.<8位随机>`）与高熵随机 `IPC_MAGIC_CODE`（严格落在安全事务码段 `0x00530000..0x007EFFFF`，避开 AOSP 与 OEM 保留码）；
   * 桌面应用名伪装为 `System Calibrator`（支持禁用桌面 Alias 图标），Release 版开启 R8 全量混淆并剥离所有项目名称字符串及调试日志。

### 3.2 零破坏可逆架构（专治 ColorOS / HyperOS / OriginOS）

#### 1. 纯内存替代写盘（Zero-Disk OS Mutation）

所有核心管控均在 `system_server` 内存态拦截与协同完成，不写入任何系统持久化文件：

* **ColorOS Hans / OFreezer 温和接管 (`OemHansPlugin`)**：
  * **绝不**停用 `com.oplus.athena`，也**绝不**改写系统属性或持久化规则文件。
  * 仅在探测到 `oplus-services.jar` 中的 `com.android.server.am.OplusHansManager` / `HansCGroup` / `OplusHansImportance` 等类存在时激活插件。
  * **冻结粒度协同设计（关键）**：ColorOS Hans 默认采用 **UID 级冻结**（`freezeCgroupUid` 写入 `/sys/fs/cgroup/apps/uid_<uid>/cgroup.freeze` 并可触发 `DestroyAllSocket` 断网），一旦冻结该 UID，其下所有进程（含 `:push`）会被一并冻死。因此：
    1. `OemHansPlugin` 在 Hans 层对命中白名单的包/UID 放行（Hook `OplusHansImportance.isImportantPkg` 或 `HansCGroup.hansFreezeLocked` 旁路冻结与断网）；
    2. **主进程依然由 AOSP `CachedAppOptimizer` 的 PID 级冻结（`/sys/fs/cgroup/.../pid_<main_pid>/cgroup.freeze`）与 LMKD 正常冻结/回收**，从而在 ColorOS 上兼得“`:push` 不被 Hans 冻杀断网”与“主进程不耗电”。
  * **OTA 自动熔断**：策略中记录上次健康启动的 `Build.FINGERPRINT`。若系统 OTA 升级导致指纹变化，首次开机 `OemHansPlugin` 自动进入 `DRY_RUN_CHECK` 模式（仅探测反射类与方法签名是否全部匹配，未通过则自动安全旁路并上报 `OTA_CHANGED_BYPASSED`，绝不挂载不确定 Hook）。
* **纯内存 Doze + 后台网络白名单 (`MemoryDozePlugin`)**：
  * **绝不**调用 `cmd deviceidle whitelist +pkg` 改写 `/data/system/deviceidle.xml`（避免卸载后永久残留）。
  * **双点协同拦截（修复单纯 Hook `DeviceIdleController` 的 eBPF 断链缺陷）**：
    1. Hook `DeviceIdleController`（`isPowerSaveWhitelistAppInternal` / `isPowerSaveWhitelistExceptIdleAppInternal`），使框架层 Doze 判定对 `memoryDozeBypass = true` 的包返回放行；
    2. **同步 Hook `NetworkPolicyManagerService` (NPMS)**（如 `isWhitelistedFromPowerSaveUL` / `updateRulesForPowerRestrictionsUL` / 内存级 `mPowerSaveWhitelistAppIds` 判定），并在策略原子热切换时主动触发 NPMS 对受管 UID 重算并同步 **`BpfNetMaps` (`FIREWALL_CHAIN_DOZABLE` 与后台网络规则)**，确保内核 eBPF 真正放行数据包。
  * 模块禁用并重启后，内存状态与内核 eBPF Map 自动恢复原厂基线，磁盘零残留。

#### 2. 可逆状态账本 (`MutationLedger`) 与“一键无痕还原”

`MutationLedger` **不用于常规保活**，仅在用户于 UI 中显式开启可选外部系统调优（如 ColorOS 关联启动/自启动白名单微调，或调试阶段的临时命令）时强制介入：
1. **改前快照**：执行任何外部持久化变更前，先读取并持久化 `{ id, targetPkg, userId, mutationType, key, originalValue, appliedValue, timestamp }` 至模块私有数据库。
2. **双级别一键恢复**：
   * **单应用还原**：关闭/删除某 App 规则时，自动逆向还原其全部已登记条目；
   * **“安全卸载前一键清空”**：按倒序回滚账本内全部条目并逐项回读校验基线恢复，再清空 `RemotePreferences` 与本地数据。

## 第 4 章：统一数据契约与核心微内核设计 (`core-protocol` & `kernel-engine`)

### 4.1 可扩展策略模型 (`KernelPolicyBundle`)

```kotlin
data class KernelPolicyBundle(
    val version: Int = 3,
    val romFingerprint: String = "",          // 用于系统 OTA 变化熔断校验
    val globalSettings: GlobalSettings = GlobalSettings(),
    val stealthAllowlistPkgs: Set<String> = emptySet(), // 显式对隐身豁免的管理器包名(如 Root/Xposed 管理器)
    val processRules: Map<String, ProcessRule> = emptyMap(), // Key: "${userId}:${pkg}"
    // 预留扩展插件槽位（未配置时不激活对应 Hook 逻辑）
    val componentBlockRules: Map<String, List<String>> = emptyMap(),
    val intentFirewallRules: List<IntentRule> = emptyList(),
    val alarmThrottleRules: Map<String, AlarmRule> = emptyMap()
)

data class ProcessRule(
    val pkg: String,
    val userId: Int = 0,                      // 支持多用户 / 工作资料 / OEM 应用分身(如 999)
    val appName: String,
    val enabled: Boolean = true,
    val pushMode: PushMode,                   // ISOLATED_PUSH / SINGLE_PROCESS / KEEP_ALIVE_ONLY
    val targetProcess: String,                // 匹配键: ProcessRecord.processName
    val wakeComponent: String? = null,
    val wakeType: WakeType = WakeType.KEEP_ALIVE_ONLY,
    val wakeAction: String? = null,
    val keepAliveAdj: Int = 200,              // 拟态合法档位 (200 或 500)，禁止负数
    val protectProcState: Boolean = true,     // A15-A17 协同保护 curProcState，防 BpfNetMaps 后台断网
    val exemptAospFreezer: Boolean = true,
    val exemptOemFreezer: Boolean = true,     // 联动 ColorOS Hans / OEM 冻结放行
    val memoryDozeBypass: Boolean = true,     // 纯内存协同 DeviceIdle + NPMS/BpfNetMaps 放行网络
    val allowResurrect: Boolean = true,
    val verifiedByAgent: Boolean = false,
    val aiSummary: String = ""
)
```

### 4.2 微内核核心组件清单

1. **无锁快照 (`PolicySnapshot`)**：
   * 每次收到新策略，在后台线程构造不可变 `PolicySnapshot`（预建 `processKey -> ProcessRule` 与 `uid -> Boolean` 扁平哈希索引，以及 `hasProcessRules` 等门控布尔位），通过 `@Volatile` 原子切换引用，热路径纳秒级只读访问。
2. **隐形双向 IPC 与冷启动配置 (`IpcBridge` + `RemotePreferences`)**：
   * **冷启动与 Direct Boot 兜底**：`system_server` 侧优先通过 `XposedModule.getRemotePreferences()`（只读）加载持久化策略并注册 `OnSharedPreferenceChangeListener` 监听变更；鉴于 Direct Boot（锁屏前）阶段不同框架实现可能延迟就绪，启动期若首次读取为空/不可用，则监听 `ACTION_USER_UNLOCKED` 或管理端首次握手时补载并刷新快照。
   * **运行时双向 RPC**：Hook `ActivityManagerService.onTransact`，拦截编译期生成的随机高熵 `IPC_MAGIC_CODE`（区间 `0x00530000..0x007EFFFF`）并校验 `Parcel` 头部魔数标签。
   * **零开销强鉴权**：在初始化及监听包更新时缓存 `moduleUid` 与 APK 签名 SHA-256 校验结果；热路径仅做 `Binder.getCallingUid() == cachedModuleUid && signatureVerified` 的 $O(1)$ 校验，未授权请求零读取、零日志直接透传原生 AMS。
   * 支持 `CMD_GET_HEALTH`、`CMD_PUSH_POLICY`、`CMD_DRAIN_AUDIT`、`CMD_RESET_BREAKER`。
3. **黑盒审计环 (`AuditRingBuffer`)**：
   * 固定 512 槽位循环数组（约 40KB 常驻内存，零动态扩容），记录 `ADJ_CLAMPED`、`FREEZE_BLOCKED`、`HANS_BYPASSED`、`DOZE_BPF_BYPASS`、`RESURRECT_OK`、`RESURRECT_SKIPPED_STOPPED`、`BREAKER_OPEN`、`STEALTH_FILTERED` 等事实事件。
4. **`ProcessGuardPlugin`（核心保活与复活插件）**：
   * **精准钳制 (`OomAdjuster` / `OomAdjusterModernImpl`)**：在 `applyOomAdjLSP` **执行前 (`before`)** 拦截，对命中 `(userId, targetProcess)` 的进程钳制 `curAdj <= keepAliveAdj`（兼容 A11 直属字段与 A12–A17 `mState`），并在 `protectProcState = true` 时将过低的 `curProcState` 托底至非缓存档位，使随后的 `lmkd` 同步、AOSP 冻结判定与 `NPMS/BpfNetMaps` 后台网络策略一并生效。
   * **AOSP 冻结兜底 (`CachedAppOptimizer`)**：拦截 `freezeAppAsyncLSP` / `freezeAppAsyncInternalLSP` / `freezeProcess`，仅放行命中的 `targetProcess`，不影响同包主进程的 PID 级正常冻结。
   * **全路径死亡监听与安全复活**：同时覆写 **`cleanUpApplicationRecordLocked`（覆盖 `removeTask` 划卡清理经 `removeProcessLocked` 且提前 `unlinkToDeath` 的路径）** 与 `appDiedLocked`（按 `(pid, processName)` 去重）：
     1. 异步延迟 1.5s 出锁至专用 Handler 线程执行；
     2. 实时查询 `PackageManager` 校验 `ApplicationInfo.FLAG_STOPPED`（严格尊重用户在系统设置的“强行停止”）；
     3. 二次存活检查（若已自行重启则跳过）；
     4. 退避熔断保护（30s 内超过 3 次触发 5 分钟熔断冷却并写入 `BREAKER_OPEN`）；
     5. 在 `Binder.clearCallingIdentity()` 上下文中，通过 `DeviceIdleInternal` 授予 10s 临时后台允许白名单，再按对应 `UserHandle.of(rule.userId)` 精准拉起 `wakeComponent`（`startServiceAsUser` / `sendBroadcastAsUser`）。
5. **`StealthHidePlugin`（系统级自我隐身插件）**：
   * **跨版本 Hook 点**：
     * Android 13–17（API 33–37）：Hook `ComputerEngine#shouldFilterApplication`、`getPackagesForUid`、`getNameForUid`、**`getNamesForUids`**、`getPackageUid`；
     * Android 11–12（API 30–32）：Hook `AppsFilter` / `AppsFilterBase#shouldFilterApplication` 与 `PackageManagerService` 对应 UID 查询接口。
   * **防自伤白名单（必选）**：对以下调用方**绝不隐藏自身**，防止破坏 Root 授权与正常管理：
     1. 系统/核心 UID（`callingUid < 10000`）；
     2. `Synapse` 自身（`callingUid == cachedModuleUid`）；
     3. 当前默认桌面（Home Role Holder）与已登记的 Root/Xposed 管理器（KernelSU / APatch / Magisk / LSPosed / Vector 管理器，动态缓存其 UID）。
   * **防御性防崩守卫**：对 `isolatedProcess`（UID 90000+）等特殊调用方可能导致的 `callingSetting == null` 做严格判空，杜绝 Android 15–17 下的 `system_server` NPE。

## 第 5 章：端侧 Root AI 诊断智能体 (`agent-runtime`)

### 5.1 安全防呆与运行机制
* **常驻管道 (`PersistentRootShell`)**：仅在调试会话期间开启一条交互式 `su` 管道（UUID Marker 切分 stdout/stderr 与退出码），命令延迟 < 5ms，会话结束立即关闭。
* **高风控应用护栏 (`RiskAppGuard`)**：自动识别银行、支付、强反作弊手游特征，**禁止**对其执行 `probe_wake_component`（防止异常冷启动触发风控上报），仅允许只读诊断与保守 `KEEP_ALIVE_ONLY` 建议。
* **绝对不写外存**：禁止向 `/sdcard` 或 `/data/local/tmp` 写任何临时文件。
* **ReAct 循环控制**：`maxSteps = 8`，单次探测遇报错自动分析 Logcat 并补齐 `Action` 或切换组件重测；若无法在不拉起主进程的情况下独立唤醒子进程，自动优雅降级为 `KEEP_ALIVE_ONLY`。

### 5.2 参数化诊断工具集 (`AgentToolRegistry`)

| 工具名 | 核心诊断能力（含 Android 15–17 与 ColorOS 增强） |
| :--- | :--- |
| **`inspect_manifest(pkg, userId)`** | `ZipFile(baseSourceDir)` 直读 APK 二进制 `AndroidManifest.xml`（`base.apk` 含合并后的清单，必要时按需解析 `resources.arsc` 字符串引用），按进程分组提取 Service/Receiver、exported 状态及 Intent Action（规避 `AssetManager` Cookie 陷阱）。 |
| **`inspect_live_state(pkg, userId)`** | 1. 进程快照 (`ps`) 与 RSS 内存；<br>2. `oom_score_adj` 与自适应 cgroup v2 冻结态（自动探测 `/sys/fs/cgroup/apps/uid_*/pid_*` 与 `/sys/fs/cgroup/uid_*/pid_*`）；<br>3. **活跃长连接定位**：碰撞 `/proc/<pid>/fd` `socket:[inode]` 与 `/proc/net/tcp`、`/proc/net/tcp6`（含 IPv4-mapped IPv6 `st=="01"`）以及 `/proc/net/udp(6)`（覆盖 QUIC/UDP 推送通道），精准锁定握有长连接的子进程；<br>4. **A17 & OEM 专项遥测**：SDK 37 上采集 `am memory-limiter status`、cgroup `memory.current`/`memory.events` 与 **`dumpsys jobscheduler <pkg>`** 挂起时长统计；ColorOS 上检索 `OplusHansManager` 冻结/断网记录。 |
| **`probe_wake_component(...)`** | **沙盒试错核心探针**：前台避让检查 -> 记录进程基线 -> 仅 `kill -9` 目标子进程 -> 通过 `cmd deviceidle tempwhitelist -d 10000 <pkg>` 临时豁免并用 `am start-service --user <userId>` / `am broadcast --user <userId>` 拉起 -> 2 秒后采集：**目标子进程存活与 RSS、主进程是否被误伤拉起、前台 Activity 栈有无弹窗、`logcat -d -v epoch -t 300` 实时堆栈**。 |
| **`query_kernel_audit(pkg)`** | 通过 AMS Magic Binder 拉取 `AuditRingBuffer`，核查内核层拦截、放行、eBPF 白名单同步与熔断历史。 |
| **`read_recent_logs(pkg, lines)`** | 读取该包名 Logcat 并经 Root Shell 解析 **`dumpsys activity exit-info <pkg>`**，精准区分 LMKD、A17 `MemoryLimiter:AnonSwap`、用户强停或应用自身崩溃。 |
| **`commit_and_verify_rule(...)`** | 写入 `RemotePreferences` 并通过 Magic Binder 推送内核原子热切换（不写系统盘，同步刷新 NPMS/eBPF）；开启 `run_e2e_test` 时当场 `kill -9` 子进程，3 秒后验收 **`system_server` 内核是否成功无感救活**。 |

## 第 6 章：客户端交互、基建协同与扩展路径

### 6.1 管理端 UI 核心板块 (`app`)
1. **内核健康与兼容看板**：显示 Magic Binder 握手状态、当前 Android 版本（含 API 37 适配与 `OomAdjusterModernImpl` 状态）、AOSP/OEM Hook 挂载状态（如 `OemHansPlugin: OK / BYPASSED_ON_OTA`、`MemoryDozePlugin(NPMS+eBPF): OK`）。
2. **AI 调试终端 & 批量托管队列**：支持单 App 流式对话精调（实时查看 AI 查连接、试探组件、看报错自纠）与多 App 批量自动托管；响应式自适应大屏布局（满足 Android 17 `sw >= 600dp` 强制规范）。
3. **可逆还原中心（Clean Restore）**：随时查看 `MutationLedger` 账本（默认零记录），提供“单应用重置”与“卸载前一键无痕清空还原”。

### 6.2 与底层 Root 基建的隐身协同
为通过严苛的金融/游戏环境检测：
* **底层推荐**：**KernelSU / APatch**（开启进程级 `Umount`），或 **Magisk + Zygisk-Next + Shamiko**，将高风控 App 全部加入底层排除列表；
* **框架推荐**：**LSPosed v2.0+ 或 Vector（`libxposed` API 101/102）**，使用 `modern` 变体（零 Manifest Xposed 特征），作用域由 `scope.list` + `staticScope=true` 锁死为 `android`，配合内置 `StealthHidePlugin` 实现全链路零暴露。

### 6.3 未来无侵入扩展路线
得益于 `KernelPlugin` 与 `AgentToolRegistry` 的双端插件化设计，未来新增能力只需新增 1 个微内核插件 + 1 组 Agent Tool：
1. **双向墓碑与链式唤醒拦截**：拦截同门 SDK 跨应用 `ContentProvider`/隐式广播唤醒并写入黑盒环，AI 一键溯源“谁唤醒了谁”。
2. **续航侦探（WakeLock / Alarm 精确限流）**：增加 `batterystats`/`alarm` 工具定位夜间掉电元凶，在 `AlarmManagerService` 做对齐推迟与 `WakeLock` 超时截断。
3. **无痛组件精简**：利用 `system_server` 软拦截广告/统计组件启动（不调用 `pm disable`，100% 可逆）。
4. **智能 Intent 防火墙**：审计 `ActivityStarter` 跨应用跳转写入黑盒环，由 AI 识别“摇一摇跳转”特征并拦截。
5. **自然语言情景自动化**：AI 将自然语言需求编译为监听屏幕、前后台、蓝牙、充电状态的轻量 ECA 规则在内核本地执行。
