## Phase 2：`system_server` 微内核底座与四大插件 (`kernel-engine`)

### Task 2.1 微内核基础设施 (`kernel-engine/core`)
- [x] `HookBridge.kt` & `SafeHook.kt`：统一 Hook 抽象与异常隔离舱
- [x] `PolicySnapshot.kt` & `PolicyManager.kt`：不可变 `@Volatile` 快照、$O(1)$ 哈希索引、`RemotePreferences` 只读加载 + Direct Boot（`ACTION_USER_UNLOCKED`）补载

- [x] `KernelPlugin.kt` & `MicroKernel.kt`：插件注册表、健康聚合、Direct Boot 监听与热切换分发

## Phase 3：端侧 Root AI 诊断智能体与可逆账本 (`agent-runtime`)

> 工程优化：`agent-runtime` 采用纯 Kotlin JVM 模块（零 Android SDK 耦合），可在 Android 端与独立 JVM/CI 环境直接编译与单测。

### Task 3.1 底层执行管道、风控护栏与事务账本
- [x] `PersistentRootShell.kt`：单条交互式 `su` 管道（UUID Marker 切分输出与退出码，超时回收，阻断外存写入）
- [x] `RiskAppGuard.kt`：金融/支付/强反作弊特征护栏
- [x] `MutationLedger.kt`：外部持久化变更事务账本（改前快照、单应用还原、卸载前一键倒序回滚与校验）

### Task 3.2 遥测与 APK 解析器
- [x] `BinaryAxmlParser.kt`：纯 Kotlin 二进制 `AndroidManifest.xml` 解析器（配合 `ZipFile` 提取进程分组、Service/Receiver、`exported` 与 Actions）
- [x] `ProcNetParser.kt`：碰撞 `/proc/<pid>/fd` 与 `/proc/net/tcp(6)`（含 IPv4-mapped IPv6 `st=="01"`）及 `/proc/net/udp(6)`
- [x] `Android17TelemetryParser.kt`：`dumpsys activity exit-info`（识别 `REASON_OTHER` + `MemoryLimiter:AnonSwap`）、`dumpsys jobscheduler`、自适应 cgroup v2 探针及 ColorOS Hans 日志解析

### Task 3.3 六大参数化工具与 ReAct 编排器
- [x] `AgentToolRegistry.kt`：6 大诊断与验收工具（含 `cmd deviceidle tempwhitelist`、`--user <userId>`、前台避让与 E2E 救活校验）
- [x] `LlmClient.kt`：零额外重依赖的 OpenAI 兼容 Function Calling HTTP 客户端
- [x] `ReActOrchestrator.kt`：`maxSteps = 8` 流式 ReAct 调度、报错自纠与降级引导

### Task 3.4 Agent 单元测试
- [x] `AgentRuntimeTest.kt`（覆盖 `ProcNetParser`、`Android17TelemetryParser`、`RiskAppGuard`、`MutationLedger`、`ReActOrchestrator`、`BinaryAxmlParser`）— **`:agent-runtime:test` 0 警告全部通过**
